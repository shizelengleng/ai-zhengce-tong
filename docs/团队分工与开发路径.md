## 一、共同基础：三人都要掌握的

### 1.1 必须安装的软件

| 软件 | 用途 | 谁必须装 |
|---|---|---|
| 微信开发者工具 | 写/跑/预览小程序（唯一开发环境） | P2（P1/P3 可选装） |
| Git（GitHub Desktop 或命令行） | 代码协作，三个人的代码合一 | **三人** |
| 微信 | 日常沟通 | 三人 |
| 腾讯文档 | 政策数据表、进度表共享 | 三人 |

> 建议：命令行 Git 你们不熟的话，**装 GitHub Desktop（图形界面）**，鼠标点几下就能提交/推送，对新手最友好。

### 1.2 必须理解的 5 个概念（不要求会写，但要说得出）

1. **小程序 = 一堆文件**：每个页面是 `wxml`（结构）+ `wxss`（样式）+ `js`（逻辑）三个文件。
2. **云函数 = 一个"后台小程序"**：前端调用它，它去查数据库、调 AI、把结果返回。
3. **API Key = 钥匙**：调 AI 要出示钥匙（在 `.env` 里，**绝不能提交到 GitHub**）。
4. **RAG = 先查资料再回答**：先搜政策（向量检索），再把资料喂给大模型，让它照着回答。
5. **Git = 时光机 + 合订本**：三个人的代码合并到 GitHub 一个仓库，还能回退。

### 1.3 Git 协作铁律（三人都要遵守）

1. 每天开工前 `git pull`（把队友的最新代码拉下来）。
2. 只提交**自己负责的文件**，不碰队友的文件（按第七章的归属）。
3. 提交前**绝不 `git add .`**，只 `git add 具体文件`——防止把 `.env`、临时文件提交上去。
4. 提交信息写清楚："我改了啥"（如 `feat: chat页接上ask云函数`）。
5. 有冲突先问队友，不硬覆盖。
6. `.env`、`node_modules`、`__pycache__`、`.DS_Store` 永远不进仓库（`.gitignore` 已配好）。

## 二、P1 队长·统筹+数据治理

### 2.1 职责清单（按优先级）

1. **项目排期与进度管理**：维护进度表，每天催进度、同步风险。
2. **赛事对接**：确认报名信息、记住提交要求与截止时间（8/31 24:00）。
3. **政策知识库建设（牵头）**：建腾讯文档表格，把 30-50 条政策整理出来，分配分类给 P2/P3 一起填，最后汇总校验。
4. **演示视频 + 问答脚本**：8/29 用手机真机录 2-3 分钟演示，提前写好提问清单。
5. **作品说明 + 原创承诺书 + 打包提交**：8/30 前完成，8/31 发邮箱。

### 2.2 需要掌握的技术/工具

| 工具 | 要会到什么程度 |
|---|---|
| 腾讯文档表格 | 建表、列字段、多人协作、导出 CSV/JSON |
| 资料整理 | 从政策网页/公众号提取"标题/关键词/答案/出处/电话"五要素 |
| 手机录屏 | 手机自带录屏，边演示边录 |
| Git 基础 | 4 个命令：`git pull` / `git add 文件` / `git commit` / `git push`（或用 GitHub Desktop 点按） |
| 压缩打包 | zip 压缩，命名"板块名称+团队名称+作品名称" |

### 2.3 每天固定动作

- 早上：更新进度表（昨天完成 / 今天计划 / 谁卡住了）。
- 晚上：群里 10 分钟同步，记录到腾讯文档。
- 每天至少整理 5-8 条政策（这是全组的地基）。

### 2.4 政策知识库整理方法（P1 负责）

1. 建表格，列名：`分类 | 标题 | 关键词(逗号分隔) | 通俗答案 | 官方出处 | 出处链接 | 咨询电话`。
2. 按分类分工：P1 管"政务办事/社保"，P2 管"教育/医疗"，P3 管"住房/就业创业+港澳青年"。
3. 每条政策 10 分钟以内能填完，来源必须是官方（政府网/公众号/12345）。
4. 填完导出成 JSON，交给 P3 导入数据库。

## 三、P2 前端·产品+界面

### 3.1 职责清单（按优先级）

1. **小程序骨架**：创建项目、填 AppID、跑通"你好世界"。
2. **4 个页面**：`chat`（聊天）、`category`（分类）、`detail`（详情）、`mine`（我的）——用 AI 生成的代码粘贴进去并调通。
3. **交互细节**：输入框、发送按钮、防连点、加载态"正在思考…"、消息气泡、快捷问题卡片、答案里出处可点击。
4. **调用云函数**：把页面接上 `ask` / `getPolicies` / `getHistory` / `saveHistory`。
5. **美化与真机测试**：调样式、处理键盘顶起、在真机预览录屏给 P1 做视频。
6. **参与数据**：负责"教育入学/医疗保障"两个分类的政策整理（8/21-22）。

### 3.2 需要掌握的技术（前端入门即可）

| 知识点 | 要会到什么程度 |
|---|---|
| 微信开发者工具 | 会导入项目、编译、预览、真机调试、看 Console/Network 报错 |
| 小程序文件结构 | 知道 `app.json`（全局配置）、`pages/页面名/*.wxml|wxss|js|json` 是啥 |
| WXML 标签 | 会用 `view / text / input / button / scroll-view / image` |
| WXSS 样式 | 会用类选择器、`flex` 布局、`rpx` 单位（1px≈2rpx） |
| JS 逻辑 | 会 `data` 定义、`bindtap` 绑事件、`setData` 改界面、`wx.cloud.callFunction` 调云函数 |
| 调试 | 能看懂 Console 红字、Network 里请求成功/失败 |

### 3.3 页面开发顺序（先静态后接后端）

1. 先做 `chat` 页**静态版**：输入框 + 发送按钮 + 假气泡（不用后端也能看效果）。
2. 再接入 `ask` 云函数：点发送 → 调云函数 → 把回答显示成气泡。
3. 再做 `category` 页：从云函数 `getPolicies` 拉分类列表。
4. `detail` 页：点政策 → 看全文+出处+电话。
5. `mine` 页：历史记录 + 关于。
6. 统一美化 + 真机测试。

### 3.4 开发路径（对应排期）

- 8/20：装工具、建项目、跑通"你好世界"。
- 8/21-22：填数据（教育/医疗分类）+ 学小程序基础。
- 8/23-24：搭 `chat` 静态页。
- 8/25-26：接云函数，做全 4 个页面。
- 8/27-28：美化、边界处理（网络失败提示）、真机预览。
- 8/29：配合 P1 录演示视频。

## 四、P3 后端·AI链路

### 4.1 职责清单（按优先级）

1. **开通云开发**：在微信开发者工具里开通云开发环境，创建 4 个云函数骨架。
2. **政策数据入库 + 向量化**：把 P1 的 JSON 导入 `policies` 集合，写脚本批量调阿里云 embedding 生成 `vector` 字段。
3. **`ask` 云函数（核心）**：接收问题 → 转向量 → 余弦相似度取 Top3-5 → 拼 Prompt → 调智谱 GLM → 返回答案+出处。
4. **其余云函数**：`getPolicies`（分类/详情）、`saveHistory`、`getHistory`。
5. **AI 接入与容错**：把 `.env` 的 Key 配成云函数环境变量；实现"主力 glm-4-flash → 备选 glm-4.7-flash → 兜底 sensenova"的切换。
6. **参与数据**：负责"住房/就业创业+港澳青年"两个分类（8/21-22）。

### 4.2 需要掌握的技术（后端入门即可）

| 知识点 | 要会到什么程度 |
|---|---|
| 云开发控制台 | 会开通环境、创建云函数、建数据库集合、配置环境变量 |
| Node.js 基础 | 会 `require`、`async/await`、`exports.main`（云函数入口） |
| OpenAI 兼容 API | 知道 `POST /v1/chat/completions` 和 `/v1/embeddings`，`Authorization: Bearer <key>` |
| 云函数模板 | 每个云函数 = `index.js` + `package.json`，`wx.cloud.callFunction` 触发 |
| 数据库操作 | 会 `collection.add / where / get / doc().update` |
| RAG 概念 | 明白 embedding 向量、余弦相似度、Top-K 检索（代码 AI 写，你负责跑通） |
| 网络请求 | 云函数里用 `axios` 或内置 `https` 模块发请求 |
| 容错 | 会 `try/catch`、重试、换模型逻辑（AI 生成，你测试） |

### 4.3 后端开发顺序

1. 开通云开发环境，建 `policies`、`conversations` 两个集合。
2. 先写一个最简 `ask`（不走向量，先调通 glm-4-flash 能回答）——**先把链路跑通**。
3. 再升级 `ask` 为真 RAG：向量检索 + Prompt 拼接。
4. 写向量化脚本：读 `policies.json` → 逐条调 embedding → 写回 `vector` 字段。
5. 补 `getPolicies` / `saveHistory` / `getHistory`。
6. 配环境变量 + 多模型切换 + 限流重试。

### 4.4 开发路径（对应排期）

- 8/20：开通云开发，建集合。
- 8/21-22：填数据（住房/就业/港澳青年）+ 导入第一批政策。
- 8/23-24：`ask` 最简版调通大模型（第一条政策能回答）。
- 8/25-26：向量化 + `ask` 升级真 RAG + 补其余云函数。
- 8/27-28：联调、容错、多模型切换。
- 8/29：配合 P1 录演示（保证链路稳定）。

### 4.5 交付物清单

- [ ] 云开发环境开通（8/20）

## 五、三方协作与接口约定

### 5.1 依赖关系

```
P1（政策数据 JSON）──▶ P3（入库+向量化）──▶ P2（页面调云函数）
        ▲                    │
        └──── 测试反馈 ◀─────┘
```

- P2 的页面依赖 P3 的云函数接口。
- P3 的数据库依赖 P1 的政策数据。
- P1 的演示视频依赖 P2 的真机 + P3 的链路稳定。

### 5.2 接口约定（必须保持一致，否则联调失败）

**云函数命名**（前后端都要用这个名字）：
```
ask           输入 { question }  → 输出 { answer, sources: [{title, source_url}] }
getPolicies   输入 { category? } → 输出 { policies: [...] }
saveHistory   输入 { question, answer } → 输出 { success }
getHistory    输入 无 → 输出 { history: [...] }
```

**policies 数据字段**（P1 表格列 = 数据库字段）：
```
category | title | keywords[] | summary | source | source_url | phone | vector(自动)
```

**分类标识**（六类，统一用英文）：
```
education(教育) medical(医疗) housing(住房)
employment(就业创业) social_security(社保补贴) gov(政务办事)
```

### 5.3 需要互相确认的 3 个时刻

1. **8/22 晚**：P1 交付首批 30 条数据 JSON → P3 确认能入库。
2. **8/24 晚**：P3 交付 `ask` 接口 → P2 确认页面能调通。
3. **8/28 晚**：三方联调完成，进入演示准备。
