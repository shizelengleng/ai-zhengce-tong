## 二、踩过的坑（重要，下次别踩）

### 坑 1：数据库导入报「格式不正确，请检查是否为 JSON Lines 格式」

- **现象**：导入 `data/documents.json`（JSON 数组格式）报错。
- **原因**：微信云开发数据库导入要求文件内容为 **JSON Lines**（每行一条记录），不是 JSON 数组（一个 `[` 包全部）。
- **关键细节**：文件**后缀必须是 `.json`**（`.jsonl` 后缀它不认），但**内容**是每行一条。
- **解决**：把数组转成 JSONL 内容，文件名仍用 `.json`：
  - `data/documents_import.json`（37 行）
  - `data/policies_import.json`（37 行）
- **规律**：以后向云数据库灌数据，一律「`.json` 后缀 + 每行一条 JSON」。

### 坑 2：ask 环境变量拼 URL 报 `Invalid URL`

- **现象**：测试时返回 `ask 云函数异常: TypeError [ERR_INVALID_URL]: Invalid URL`，报错里 URL 为 `DASHSCOPE_API_KEY=sk-ws-.../embeddings`。
- **原因**：`ask` 用 `EMBEDDING_BASE_URL/embeddings` 拼地址（`ask/index.js` 57 行）。报错说明 **`EMBEDDING_BASE_URL` 这项被填成了 `DASHSCOPE_API_KEY=sk-ws-...` 这整段**——配置环境变量时把 `名=值` 一行糊进了某一栏。
- **解决**：MD 文件里每行 `名字=值` 要拆成两栏——左边填 `=` 前的名字，右边只填 `=` 后的值。例：`EMBEDDING_BASE_URL` 的值必须是纯网址 `https://ws-.../compatible-mode/v1`，`DASHSCOPE_API_KEY` 的值必须只有 `sk-ws-...` 本身，都不带 `名字=` 前缀。

### 坑 4：云函数报「Invoking task timed out after 3 seconds」

- **现象**：修正环境变量后再测，返回 `statusCode 433, Invoking task timed out after 3 seconds`。
- **原因**：云函数**默认超时时间只有 3 秒**。`ask` 要完成「转向量 → 检索 → 拉原文 → 调 GLM 生成」，光 GLM 一个来回就好几秒，3 秒跑不完。
- **解决**：云开发控制台 → 云函数 → `ask` → 配置 → 把「超时时间」调到 **60 秒**（最大值）→ 保存。
- **规律**：任何要调外部大模型的云函数，第一件事就是先把超时调到 30-60 秒。
- **状态**：✅ 已解决，超时调 60 后 ask 正常返回答案。

### 坑 5：网页控制台「云端测试」报 `scf/Invoke ret=-3 system error`（通道坏了）

- **现象**：在云开发网页/工具内嵌控制台点「云端测试」，一直返回 `[UPSTREAM] Upstream error (ret=-3)` / `system error`，且**函数日志完全为空**（说明调用根本没到函数，是控制台的调用通道坏了，不是函数的问题）。
- **解决**：放弃控制台测试，改用**微信开发者工具「调试器 Console」直接调**（真实客户端链路）：
  1. 编译运行小程序 → 调试器 → Console
  2. `wx.cloud.init({ env: 'cloud1-d8g5hsfuke3b9e36e' })`
  3. `wx.cloud.callFunction({ name: 'ask', data: { question: '...' } }).then(r => console.log('RESULT:', JSON.stringify(r.result))).catch(e => console.error('ERR:', e))`
  4. 等 5-20 秒看 RESULT / ERR
- **验证结果**：✅ 用此方法成功跑通，返回了完整答案 + 4 条官方出处。
- **规律**：控制台「云端测试」通道若反复 ret=-3，别纠结，直接用调试器 Console 调 `wx.cloud.callFunction`。
