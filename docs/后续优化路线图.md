# 「AI政策通」后续优化路线图

> 版本 v0.1 ｜ 2026-08-22 ｜ 当前状态：`ask` 端到端已跑通（问题→向量检索→拉原文→GLM→答案带出处）
> 本文档把「还能更好」的方向记录下来，按优先级推进，不做一次性做完的承诺。

---

## 一、总体思路

现在链路通了（能回答问题、有出处），但离「演示出彩 + 可落地」还有距离。优化分四块，按 **正确性 > 演示效果 > 数据量** 排序：

1. **政策时效性**（错了会误导人，最优先）
2. **回答质量**（决定评审观感）
3. **数据库**（数据是地基，决定上限）
4. **预设追问 / 多轮对话**（演示加分项，前端配合）

---

## 二、政策时效性：政策变动了就不该再被参照

**问题**：现在 37 条政策没有"生效/失效"概念。一旦某政策被新文件替代（比如新一年招生细则发布），旧政策还会被检索到、还会被 AI 当依据，回答就过时了。

**改造方案（三层）**：

| 层 | 改动 |
|---|---|
| 数据层 | `policies` 和 `documents` 增加字段：`status`（`effective` 有效 / `expired` 失效）、`effective_date`（生效日）、`expire_date`（失效日，可选）、`superseded_by`（被哪个新文件替代，可选） |
| 检索层 | `ask` 检索前先过滤 `status == 'effective'`，失效政策**不进结果**；新增政策入库时把被替代的旧政策标成 `expired` |
| 回答层 | Prompt 保留"以最新官方公告为准"；万一检索到疑似过时内容，明确提示 |

**维护机制**：
- 建立**政策巡检表**（谁负责、多久核一次官网）——建议放在腾讯文档进度表里
- 每次新增/更新政策 → 重跑 `embed_policies.py` 重新向量化 → 导入 `policies` 集合
- 大版本更替（如每年 4 月招生季）集中核对一次

## 三、回答质量优化

| 方向 | 现状 | 优化 |
|---|---|---|
| 答案结构 | 自由发挥 | Prompt 固定"5 段标准"：**谁能办 / 要什么条件 / 怎么办 / 交什么材料 / 注意**（评审一眼看出专业性） |
| 检索范围 | Top4 | Top4 加**相似度阈值**（低于 0.5 视为无匹配 → 引导拨打 12345，不硬答） |
| 检索精度 | 单次向量 | 可加 rerank 二次排序（模型如 bge-reranker）；先不加，看效果再说 |
| 出处 | 有重复文档 | `sources` 按 doc_ids **去重**（现在同一个细则会重复出现） |
| 文号 | 有占位 | 补全 `doc_no`（如「（年度指引）」改成真实文号），出处才可信 |
| 模型 | glm-4.7-flash 主力 | 若回答偏慢/偏长，可对比 glm-4-flash 与 4.7-flash 实测选一个 |
| 兜底 | 无匹配引导 12345 | 测试几种"库外问题"（天气、房价预测等）确认能正确引导 |

**验证方法**：准备 **10-20 个测试问题**（每个分类 2-3 个 + 5 个刁钻/库外问题），逐条打分（答案是否准确 / 出处是否真实 / 是否编造）。

## 四、数据库优化

| 项 | 现状 | 优化 |
|---|---|---|
| 数据量 | 37 条 | 扩充到 **100+ 条**，每分类 10-15 条（目标 8/26 前） |
| 字段规范 | 基本齐 | `doc_no` 文号补全、`source_url` 逐一验证可访问、联系电话统一格式 |
| 向量 | 37 条已向量化 | 数据一变就重跑 `embed_policies.py`，保持 `vector` 和 `plain_answer` 同步 |
| 索引 | 无 | 云数据库给 `policies.category`、`conversations._openid + createdAt` 建索引，避免大表查询慢 |
| 历史记录 | 无限增长 | `conversations` 加保留策略（如只留最近 100 条/人），避免免费额度占用 |

**数据核对清单（每次入库前）**：
- [ ] 标题 / 文号 / 来源链接真实可查
- [ ] 分类归属正确（8 类）
- [ ] `plain_answer` 覆盖 5 段标准
- [ ] 政策仍在有效期内（失效的标 `expired`）
- [ ] `doc_ids` 关联的是对的官方原文

## 五、预设追问 & 多轮对话（演示加分）

### 5.1 预设追问（追问细节）

居民问完"怎么入学"，最好能继续点"需要什么材料""在哪办理""电话多少"，而不是重新打字。

**后端**：`ask` 返回时附 `followups: [...]`（2-3 个跟当前问题相关的追问）：
```json
"followups": ["需要准备什么材料？", "在哪里办理？", "咨询电话是多少？"]
```

**前端（P2）**：答案气泡下方渲染成可点击的追问按钮，点击即自动发问（chat.wxml 加个按钮区）。

### 5.2 多轮对话（带上下文）

把上文带进去，让"孩子上小学"之后能直接问"那转学呢"也能理解。

**后端**：`ask` 增加可选参数 `history`（最近几轮对话），检索时结合上文、Prompt 里带上上下文。

**前端（P2）**：`api.ask({ question, history })` 传最近 N 轮。

### 5.3 快捷问题卡片

聊天页已有 4 个快捷问题，可扩展为"按分类给快捷问题"（进住房类就问公租房，进教育类就问入学）。
