## 二、政策时效性：政策变动了就不该再被参照

**问题**：现在 37 条政策没有「生效/失效」概念。一旦某政策被新文件替代（比如新一年招生细则发布），旧政策还会被检索到、还会被 AI 当依据，回答就过时了。

**改造方案（三层）**：

| 层 | 改动 |
|---|---|
| 数据层 | `policies` 和 `documents` 增加字段：`status`（`effective` / `expired`）、`effective_date`（生效日）、`expire_date`（失效日，可选）、`superseded_by`（被谁替代，可选） |
| 检索层 | `ask` 检索前先过滤 `status == 'effective'`，失效政策**不进结果**；新增政策入库时把被替代的旧政策标成 `expired` |
| 回答层 | Prompt 保留「以最新官方公告为准」；万一检索到疑似过时内容，明确提示 |

**维护机制**：
- 建立**政策巡检表**（谁负责、多久核一次官网）——建议放在腾讯文档进度表里
- 每次新增/更新政策 → 重跑 `embed_policies.py` 重新向量化 → 导入 `policies` 集合
- 大版本更替（如每年 4 月招生季）集中核对一次

## 三、回答质量优化

| 方向 | 现状 | 优化 |
|---|---|---|
| 答案结构 | ✅ 5 段标准已上线 | 保持；验证是否稳定执行（尤其兜底模型） |
| 检索范围 | ✅ 相似度阈值兜底 | 用 `[score]` 日志校准阈值：看命中问题的 top1 分区分度 |
| 检索精度 | 单次向量 | 可加 rerank 二次排序（如 bge-reranker）；先不加，看效果再说 |
| 出处 | ✅ 按标题去重 | 联网来源与本地原文并存的展示，评审时讲解「可溯源」 |
| 文号 | 部分补全 | 把 37 篇 `doc_no` 占位符（如「（年度指引）」）逐篇补成真实文号 |
| 模型 | ✅ SenseNova 主力 + 智谱兜底 + 熔断 | 若回答偏慢，可对比 glm-5.2 与 glm-4.7-flash 实测选一个 |
| 兜底 | ✅ 无匹配先联网再 12345 | 测试几种「库外问题」（天气、房价预测等）确认能正确引导 |
| 延迟 | 需联网的问题约 40-50s | 演示时优先问本地库覆盖的问题（快）；连网页问题预计较慢 |

**验证方法**：准备 **10-20 个测试问题**（每个分类 2-3 个 + 5 个刁钻/库外问题），逐条打分（答案是否准确 / 出处是否真实 / 是否编造）。打分结果同时作为**演示视频的问答脚本**。

| 项 | 现状 | 优化 |

| 字段规范 | 基本齐 | `doc_no` 文号补全、`source_url` 逐一验证可访问、联系电话统一格式 |

| 索引 | 无 | 云数据库给 `policies.category`、`conversations._openid + createdAt` 建索引 |
| 历史记录 | 无限增长 | `conversations` 加保留策略（如只留最近 100 条/人） |

**数据核对清单（每次入库前）**：
- [ ] 标题 / 文号 / 来源链接真实可查
- [ ] 分类归属正确（8 类）
- [ ] `plain_answer` 覆盖 5 段标准
- [ ] 政策仍在有效期内（失效的标 `expired`）
- [ ] `doc_ids` 关联的是对的官方原文

## 五、预设追问 & 多轮对话（演示加分）

### 5.1 预设追问（追问细节）

居民问完「怎么入学」，最好能继续点「需要什么材料」「在哪办理」「电话多少」，而不是重新打字。

**后端**：`ask` 返回时附 `followups: [...]`（2-3 个跟当前问题相关的追问）：
```json
"followups": ["需要准备什么材料？", "在哪里办理？", "咨询电话是多少？"]
```

**前端（P2）**：答案气泡下方渲染成可点击的追问按钮，点击即自动发问（chat.wxml 加个按钮区）。

### 5.2 多轮对话（带上下文）

把上文带进去，让「孩子上小学」之后能直接问「那转学呢」也能理解。

**后端**：`ask` 增加可选参数 `history`（最近几轮对话），检索时结合上文、Prompt 里带上上下文。

**前端（P2）**：`api.ask({ question, history })` 传最近 N 轮。

### 5.3 快捷问题卡片

聊天页已有 4 个快捷问题，可扩展为「按分类给快捷问题」（进住房类就问公租房，进教育类就问入学）。
